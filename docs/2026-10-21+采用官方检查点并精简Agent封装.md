# 采用官方检查点并精简 Agent 封装

- 日期：2026-10-21（Asia/Shanghai）。
- 目标：在现有 `create_deep_agent` 架构内优先使用官方接口，减少重复封装。
- 范围：会话管理、执行入口、调试输出与对应测试；不升级依赖，不新增业务功能或自写模块。

## 更新内容

1. 在 `create_deep_agent` 的 `checkpointer` 参数中使用官方 `InMemorySaver`。
2. CLI直接调用 `graph.invoke`，每次仅提交新消息，由 `configurable.thread_id` 对应的官方检查点管理历史。
3. `/reset` 使用官方 `delete_thread` 删除当前线程检查点，再生成新的线程ID。
4. `--trace` 使用官方 `invoke(print_mode="updates")`，不再自写工具消息去重、JSON解析和展示结构。
5. 删除 `agents/order_agent.py` 会话包装、`exceptions.py` 和 `AgentReply`／`ToolTrace`。业务订单结构继续保留。
6. 测试改为直接验证官方图与检查点，README同步说明行为变化。

## 解决的问题

|问题|处理方式|
|---|---|
|会话历史由手写适配器维护，与官方状态能力重复|使用 `InMemorySaver` 与线程ID|
|自写消息解析、去重及回复格式增加维护成本|直接使用官方消息和原生调试输出|
|会话清理逻辑依赖自定义容器|使用官方检查点 `delete_thread`|
|异常层重复包裹框架异常|删除自定义异常模块，仅在CLI边界保留原有脱敏职责|
|原测试只间接验证会话包装|直接验证官方检查点历史、删除、隔离及调试输出|

## 保留的实现与原因

- 订单工具、JSON仓储、订单参数与返回结构属于业务逻辑，继续使用已有实现。
- `OrderToolPolicyMiddleware` 未修改：它同时执行严格订单参数校验与结构化拒绝，不仅是工具展示过滤。
- 已阅读官方工具排除中间件，确认 HarnessProfile 能同时隐藏和拒绝指定工具；本次未将现有策略改成提供方全局注册，避免扩大改动范围，也未新增替代自写代码。
- `ChatDeepSeek`、SDK重试及官方调用次数限制中间件保持现状。

## 行为变化与限制

- `--trace` 改为官方原生执行更新，不再返回旧的单个 `AgentReply` JSON对象；直接工具查询仍返回 `ToolResult` JSON。
- 进程内历史交由官方检查点管理，不再承诺固定8轮或失败时自动回滚。失败运行的部分状态可能留在检查点，可用 `/reset` 清理。
- 尚未提供逐字输出参数；本次没有自写流式协议或解析器。
- 检查点仅保存在内存，不能跨进程恢复；调用方必须保证同一线程绑定同一可信用户。
- 未进行长会话总结效果评测，单次真实调用不代表整体效果指标。
