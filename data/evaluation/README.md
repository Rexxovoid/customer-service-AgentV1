## 模式

- `live_agent`：真实模型，读取固定业务数据，不代表真实平台服务。
- `controlled_agent`：真实模型决策，使用明确标识的固定知识或故障注入；不能用于宣称真实RAG准确率。fixture标签由独立测评包实现，不进入生产降级流程。
- `live_rag`：真实RAG检索和选择；E18/E19/E21/E22必须先人工标注相关文档、原文及适用前提，才能计入准确率。E21左键、E22空格键仍pending，不自动把当前结果标成金标。

每个案例默认初始售后状态为空、独立会话、独立测试SQLite；E16由可信测试准备代码设置退款终态。同一案例各轮共享状态；跨案例不得共享。on_fail默认stop，检查失败立即停止并记录未执行轮次；on_pass可设stop。初版支持条件停止/继续，不支持自由跳转。

## 人工核对

`confirmation_cases.jsonl`含E31/E32两条待审批案例：单句末标点的有效确认及幂等复用、重复标点无效确认。规则调用次数和解析错误原始正文由隔离回归测试验证，不能把自然语言expect自动当作机器已检查。

优化补充集 `optimization_cases.jsonl` 含E23—E30共8条，均pending，使用 `--cases` 单独运行。覆盖明确退货优先、仅规则咨询、补信息计数、严格确认、模糊日期、目标商品、购买与签收区分、仅质量咨询。默认cases.jsonl仍22条，已有审批不变。真实多商品与冲突日期另由隔离单元回归验证；仅creates=0不证明全部自然语言条件正确。

先检查输入与规则依据，再填写人工评审结果：case_id、轮次、pass/fail/unjudgeable、证据、原因、评审人别名。人工结果不能被自动评分覆盖。模型评分与人工结论冲突时单独统计并复核。

语言质量按事实正确性、知识忠实性、问题相关性、可操作性、表达质量分别0—4分；无法判断为null并附原因，不能当0分或满分。程序硬规则独立报告，严重错误不能由平均语言分抵消。

案例与参考答案禁止导入RAGFlow知识库。审批状态以cases.jsonl为准；本次保留已有E01/E02/E03的approved，修改的E06/E13仍pending，需人工重新确认。结果放在evals/results，不写回固定案例。manifest为独立发布清单；改动案例后需更新，实际实验另记录内容哈希。
